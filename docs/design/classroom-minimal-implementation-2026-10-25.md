# 网页课堂极简方案：实现约束与证据

## Overview

本记录只适用于网页课堂的响应式工作区。视觉依据是已批准的 `outputs/classroom-minimal-design-2026-10-25/prototype.html`；代码入口是 `src/components/classroom/classroom-v3.tsx`，样式收口在 `src/app/classroom-responsive.css`。项目现有 `PRODUCT.md`、`DESIGN.md` 继续保留，不将本次课堂方案提升为全站改版，也不顺带修复此前发现的全局设计偏差。

课堂内容是视觉中心：顶端保留课程身份与时间，成员席位位于授课列上方，舞台承载课件、共享与题目，聊天和同传共用一个会话区。常用操作以图标呈现，完整设置、说明与次要动作按需展开。已有权限、状态与教学能力继续通过真实业务入口工作。

`outputs/` 内的生命周期、菜单、题目与图片扩展场景是本地设计稿和验收材料；设计稿本身不证明应用已实现。以下以应用代码和注明环境的测试为准。

## Colors

前置 token 记录浅色课堂的实际取值。中性色用于页面、白色教学表面、正文和辅助信息；单一靛色用于选中、主要操作与少量提示。细分隔线用于区分区域，避免为每个动作添加独立彩色容器。

**内容优先规则。** 不用大面积强调色、持续状态说明或装饰性卡片抢占课堂内容；危险、超时、断线和录制等必要状态仍须可辨认。深色模式沿用课堂既有主题变量与对应状态色，不扩展为新的全站色板。

## Typography

沿用应用字体，不引入新的品牌字体。课程名通常为 14px、600 字重，宽屏可到 15px，小屏为 13px；正文约 14px，聊天正文行高 1.65，同传正文行高 1.7；时间使用等宽数字。输入框保持 16px 字号，避免移动浏览器因小字号自动缩放。

**短标签规则。** 图标必须有可访问名称；悬停、键盘聚焦和展开菜单提供解释。`icon-button.tsx` 为顶部、会话区、聊天/输入工具、同传、共享与白板控制提供共用 portal tooltip，避免提示被面板裁切；Escape、失焦、滚动或操作后关闭提示。必要状态、人员姓名、错误和教学内容不能随“减少常驻文字”一起隐藏。语言名称使用可读本地化标签。

## Layout

- 桌面结构为顶部栏、授课列和可选右侧会话区。成员条位于授课列内，会话区跨成员条及舞台两行；底部工具条以授课列为中心。
- 聊天与同传使用同一右栏，通过可访问 tabs 切换。桌面与手机横屏可拖动分隔线；上限为 480px 且不超过工作区的 40%。分隔线支持方向键、Shift 加速、Home/End、双击恢复默认和本地宽度记忆。
- 手机竖屏使用底部面板，保留底部工具条和安全空间；640–1024px 的手机横屏使用并排侧栏。横屏短高度必须同时保留非零舞台、成员条和输入区域，不能只检查元素存在。
- 所有成员席位始终保留，超出宽度通过成员条滚动访问；支持真实横向滚轮、触摸与 RTL。人数少时居中，不以裁剪或限制成员数解决溢出。折叠按钮有独立空间，不覆盖席位或输入区域。
- 浅色桌面顶部栏高度为 56px，手机竖屏为 52px，手机横屏为 48px。主舞台与工具条保留清楚的空间关系，不让面板切换改变内容阅读顺序。

## Elevation & Depth

主工作区通过底色、白色表面与细分隔线建立层级，右栏不添加浮动卡片阴影。菜单、图片查看器和手机底部面板在需要覆盖内容时使用克制的阴影与明确边界；悬停与聚焦反馈不能只靠阴影。

## Shapes

控制、舞台和移动面板使用前置 token 中的圆角。成员视频保留适合密集横排的小圆角；图片按实际比例完整显示，聊天内可点开查看大图。装饰性外框不应增加成员、字幕或聊天的阅读负担。

## Components

### 顶部、菜单与课程时钟

`minimal-header.tsx` 保留返回、课程菜单、时钟、必要连接/录制状态、开始上课和更多菜单。课程详情、计划时间、角色、连接信息和可用的延长/结束动作在菜单内展示。`quick-settings.tsx` 承接麦克风、摄像头、同传、界面语言、主题和高级设置；设备失败须有可见错误。

`lesson-clock.ts` 以运行时状态和服务端校正时间计算等待、待开始、上课、超时、临近结束、已结束六种阶段。超时与最后一分钟使用不同警示层级；时钟只是展示，不能在本地倒计时归零时自行结束媒体。

### 成员与共享

席位姓名持续可见；管理动作在悬停、聚焦或触摸激活后显示。共享者席位使用账户头像、姓名与共享状态占位，避免再展示一条重复摄像头视频；手机上的共享状态与头像、媒体状态徽标分别占位，不能互相覆盖。所有其他成员仍保留席位和音频。

桌面 Chrome/Edge 的“共享＋人像”使用单条 1080p、15fps Canvas 合成视频；“仅共享”使用 720p、15fps。共享期间主摄像头继续本地采集，独立视频发布按合成状态退出和恢复。接收端以 Full HD 聚合像素预算优先接收共享，剩余预算用于小流；具体生命周期、回滚与验收边界见 `docs/classroom-share-portrait-2026-10-25.md`。

### 聊天、同传与图片

会话区保留聊天草稿、阅读历史位置和“回到最新”行为；同传具有独立跟随状态，设置按需展开。切换 tab 不应重置输入或强迫跳回底部。断线恢复以权威快照同步，RTM 用于失效通知，轮询与重连补齐状态。

图片从输入区选择，先预览再发送，可在聊天中查看大图。服务器只接受 5MB 以内的静态 JPEG/PNG/WebP，Sharp 以 1600 万输入像素为上限校验，校正方向后缩至最长边 1920px 并转 WebP。上传记录绑定课次、上传者与源文件哈希，重试保留同一身份。图片通过有鉴权的消息代理读取：必须符合该条消息的实际受众、发送者绑定与未撤回状态，并返回 `private, no-store`。全局撤回后后续图片请求失效；教师/助教的禁言同时约束文字和图片，不能仅隐藏客户端按钮。

### 聊天内教学活动

老师/助教从聊天创建投票、单选/多选/判断题、测验及书面任务，可粘贴材料或请求 AI 生成/润色草稿。AI 结果必须先预览、明确采用、保存，再由老师主动发布题目；生成操作不能自动发布。活动关闭后可批改、发布结果、查看统计和导出 CSV，课后独立结果页继续读取同一数据。

学生答案按账户保存并带版本，重新进入课堂可恢复已提交内容；跨设备冲突须明确提示并允许读取已保存版本，不能静默覆盖。服务端验证老师/助教权限、课次范围、答案可见性和活动状态；一个课次至多有一个活动进行中，答案提交与关闭并发受事务及数据库约束保护。共享舞台投影隐藏不该显示的答案信息。

活动数据已具备后续课后 AI 分析的持久化基础；本次没有实现自动汇入全局课程总结，不得将草稿生成或结果页等同于该集成完成。

### 数据库变更

本功能新增三份 migration，需要随应用一起进入目标环境的正常迁移流程：

| Migration | 作用 |
| --- | --- |
| `20261001100000_classroom_activities` | 活动、每账户答卷、版本、发布与展示状态；创建请求唯一性；每课次单个进行中/展示中活动的部分唯一索引。 |
| `20261002110000_activity_creation_fingerprint` | 不可变创建请求指纹，区分兼容重试与内容不同的重复请求。 |
| `20261025090000_classroom_chat_images` | 图片归属、私有对象键、源哈希、尺寸及体积记录，关联实际课次。 |

完整 migration 链已在隔离 PostgreSQL 上验证，并检查 Prisma schema 一致性与原课程/课件数据保留。工作区既有的课次时区 migration、排课与原生客户端改动不属于本次交付；本次没有操作生产数据库。

## Do's and Don'ts

- 延续课堂局部的内容优先、图标提示和单一会话区；保留键盘、触摸、本地化与明确权限反馈。
- 验收必须从教师触发到学生实际接收、持久化和重入恢复闭环，不用纯静态图或单个 API 成功代替整条教学链。
- 不把本记录当作全站 `DESIGN.md` 的替代，也不将本地样例、替身媒体或隔离数据库标成线上验收。
- 不承诺真实 RTC、设备性能或计费收益；不宣称自动课程总结已经接入。

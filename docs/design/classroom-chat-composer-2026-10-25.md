# 聊天输入区设计与实现记录 · 2026-10-25

## Overview

本次是既有课堂极简设计稿的局部扩展。独立原型位于 `outputs/classroom-interaction-design-2026-10-25/composer.html`，沿用同目录 `style.css`、图标和互动题目演示，在 `composer.css`、`composer.js` 中实现输入区布局与状态；`composer-demo.js` 承接既有互动行为。方向依据见 `.impeccable/review/composer-20261025/direction.json`。

确定采用三层顺序：**顶部图片／教师 AI 出题工具，中部透明无常驻边框正文，下部左侧计数与右侧发送**。图片和 AI 入口放在输入前，先表达可添加的内容类型；发送放在正文后，形成“选择内容 → 输入 → 检查 → 发送”的阅读和操作顺序。工具不占用正文横向空间，长文增长时也不挤占独立的发送位置。学生只显示图片工具，教师额外显示 AI 出题。

用户随后明确要求“需要实现”，现已将该布局接入真实课堂代码。实现入口为 `src/components/classroom/classroom-chat-panel.tsx`，样式在 `src/app/classroom-responsive.css`；共享字数规则在 `src/lib/classroom/chat-content.ts`，图片说明解析在 `src/lib/classroom/chat-image-message.ts`，实际消息写入限制在 `src/app/api/courses/[id]/classroom/messages/route.ts`。实施方向见 `.impeccable/review/composer-live-20261025/direction.json`。本文记录设计、代码实现及本地真实浏览器验收；本轮不包含部署。

根目录 `DESIGN.md`、`PRODUCT.md` 保留；本次不建立新的全局视觉系统，也不创建或改写 `.impeccable/design.json`（初次记录时该侧车不存在）。本文只记录局部选择，不将其推广为所有表单的规则。

## Colors

沿用原型 `style.css` 的白、灰、靛蓝体系：白色聊天表面，正文 `--ink`（`#20242b`），次要文字／工具 `--muted`（`#657080`），主要操作与键盘焦点 `--accent`（`#4f46e5`），工具悬停淡底 `--tint`（`#eeedff`），区域分隔 `--line`（`#e5e7ed`）。达到字数上限时，计数和短提示使用棕色（`#955a12`）。

正文自身保持透明；原型白色来自聊天容器，顶部的一像素分隔线划分消息列表和编辑区域，不形成包裹 textarea 的底框。真实代码沿用现有 light/dark 变量：正文 `--classroom-frost`、次要内容 `--classroom-mist`、焦点／达到上限提示 `--classroom-iris`、分隔 `--conversation-line`，适应课堂既有主题。真实上限提示随主题使用强调色，未复制原型的固定棕色。独立发送保持靛蓝填色（`#4f46e5`）。

## Typography

沿用原型系统字体栈：`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", sans-serif`。周边课堂消息／标签以既有约 12px 密度为背景；本次正文桌面为 13px、手机为 14px，行高均为 1.7。计数、上限提示和附件说明使用 11px，数字采用等宽排列以减少长度变化时的跳动。

真实正文桌面仍为 13px／1.7；760px 以下为 16px／1.7，作为避免 Safari 输入聚焦缩放的设备适配，与原型 14px 有明确差异。真实计数／上限提示为 11px。以上不覆盖根设计文档的全局字号，也不把小字号提升为未来所有课堂界面的规范。

## Layout

编辑区使用纵向 flex 布局，与消息列表分离且不参与压缩。桌面内边距为 `8px 16px 12px`；工具行高 36px；正文最小高度 76px、最大高度 144px；底行最小高度 40px。手机内边距为 `6px 13px 10px`，工具行高 34px，正文最小高度 68px、最大高度 120px。正文达到最大高度后内部滚动，工具和底行保留。

底行以两端对齐布局放置左侧状态和右侧发送；空白正文时计数隐藏，左侧不显示占位数字或键盘说明。桌面发送按钮为 38×36px，手机为 40×36px。工具区桌面图标按钮为 34×34px，手机为 36×34px。

上述外边距和预览切换属于原型。真实编辑区使用既有聊天面板内边距，表单自身为 `6px 0 0`；760px 以下采用手机样式。真实正文同样桌面 76–144px、手机 68–120px，由内容与可用宽度变化自动调整高度，上限后内部滚动。底行高度 40px，桌面发送 38×36px、手机 40×36px。真实浏览器已覆盖 390px 与 320px 布局，附件状态发送按钮仍在面板内；手机物理软键盘弹起与设备安全区仍需设备证据，不能用桌面模拟视口证明。

学生紧凑布局中，聊天可见时隐藏额外的悬浮题目重开入口／答案胶囊，避免覆盖输入区；聊天卡片仍可重开题目，聊天关闭时保留原有悬浮入口。该调整只为输入区与互动题目的共存，不删除题目能力。

## Elevation & Depth

正文和发送区保持平面，无 textarea 阴影。通过纵向留白、顶部区域分隔线、工具悬停淡底和发送按钮填色建立层级。工具 hover／键盘 focus 时出现深色文字提示；该提示属于临时辅助层，不为编辑器增加常驻边框。

## Shapes

正文为无边框、无底色、无圆角外框的书写区域。键盘 `focus-visible` 时保留 2px 靛蓝轮廓、3px 外偏移和局部 4px 圆角，以满足定位焦点的需要；“无常驻边框”不删除可访问焦点。

发送与工具按钮沿用局部 8px 圆角，附件示例缩略区为 6px；这些值继承当前极简稿的局部组件语汇，不替换根设计文档中的按钮／卡片圆角体系。

## Components

### 工具与附件

图片按钮始终位于正文上方。教师 AI 出题按钮紧随其后，真实代码以 `canManage` 决定其可见性。图标使用 SVG，按钮带可访问名称和提示。原型 AI 入口打开既有题目演示；真实代码打开现有课堂 AI 出题流程，没有另建演示数据路径。

原型图片按钮只显示固定“链表示意图.png”示例，发送时转成文件名文本。真实代码保留现有图片文件选择、粘贴、上传与消息协议；真实预览缩略图、文件名和移除按钮位于工具与正文之间，可发送仅图片或图片加说明。附件预览为 82×44px，长文件名单行省略并保留完整提示。原型固定附件仍只用于设计对照。

### 正文、计数与上限

上限为 **1200 个 Unicode 码点**，前后端共享 `CLASSROOM_CHAT_MAX_CHARACTERS` 与 `chatCharacterCount`，使用 `Array.from(value).length` 计数；前端 `limitChatContent` 截断，服务端拒绝超限请求。汉字、字母、空格、换行都计入；补充平面 emoji 按一个码点计，组合 emoji 可能含多个码点。这不是用户感知字形簇计数，也不是 UTF-16 长度。纯文本与图片说明解析采用同一上限。

零长度时隐藏计数；输入任意字符后显示 `n / 1200`，包括仅空白内容。达到 1200 时显示“已达 1200 字”，已有内容仍可发送；超长输入／粘贴在非组词状态截断到 1200 个码点。输入法组词期间不截断，`compositionend` 后再统一计数与处理上限，因此临时组词值可能超过上限。

### 发送

正文去除首尾空白后为空且没有附件时禁用发送；有正文或附件时启用。桌面 Enter 提交、Shift + Enter 换行；组词 Enter 不提交。真实代码在 760px 以下或粗指针设备保持 Enter 换行，通过下方按钮提交。空白字符仍计数，但不能单独作为消息提交。

独立原型仍使用 localStorage 键 `classroom-composer-design-v1`。真实课堂继续沿用原有消息请求和持久化路径、乐观消息、幂等重试及图片上传回执。发送中显示状态与加载图标，正文只读；成功后清空正文和附件，失败恢复待发送正文并保留附件与已上传回执，同一失败内容重试复用 `clientMessageId`。完成请求后焦点返回正文。本次布局调整没有替换这些既有恢复机制。

历史原型阶段的浏览器验证来自主任务执行：39 字计数、1200 上限状态、1201 输入截断、发送后重置、空白计数隐藏、示例附件显示／移除、学生隐藏 AI，以及 320px 无横向溢出。截图保存在 `.impeccable/review/composer-20261025/`：`desktop.png`、`mobile-empty.png`、`mobile-typing.png`、`mobile-limit.png`、`mobile-attachment.png`、`mobile-student.png`、`mobile-320.png`，覆盖桌面 1440×1000、手机 390×844 与 320×740 预览。真实中文输入法和手机软键盘未进行设备验证；源码包含相应保护逻辑，不等同于设备验收。

独立收尾评审记录在同一 review 目录的 `finish-review.md`，结论为 `disposition: ship`，五个评审部分完整，六张指定必需截图均有效，本次输入区范围内无待修复的实质问题。该结论来自原型代码与截图审查，允许交付设计稿；不代表业务上线或真实设备验收。原始检测记录有 8 项主要提示和 34 项建议，独立评审已按范围核对既有字体回退、周边间距／裁切等提示；本次辅助文字已修正为 11px。截图后未再修改 UI。

## Do's and Don'ts

- Do 保持工具 → 正文 → 底行的 DOM 和视觉阅读顺序；底行左计数、右发送。
- Do 让长文在正文内部滚动，保留工具和发送，并保留键盘可见焦点。
- Do 用同一 Unicode 码点口径处理计数、截断与服务端校验，单独验证中文组词。
- Don't 给此聊天正文恢复常驻边框或填色底框，也不要把发送放回正文内部。
- Don't 向学生显示教师 AI 出题入口；保持现有权限校验配合。
- Don't 把原型固定示例附件、本地消息或预览截图作为真实上传、AI、消息发送与设备验收的证据；真实 API 测试也须保留其环境边界。

未规范化或修复的既有漂移：根 `DESIGN.md` 的全局输入底框、字号与圆角描述和当前极简原型存在局部差异，章节格式也未按新版模板整理；本任务是局部设计记录，因此保留既有全局文件，并未将这些差异改写为新的全局规则。

## Overview

这是已批准极简课堂风格的局部扩展，记录真实代码中的互动题卡、出题和学生浮层。全局视觉规范仍由根目录 `DESIGN.md` 决定，`PRODUCT.md` 保持原样；本次未创建或改写 `.impeccable/design.json`（检查时该文件不存在）。本文不建立新的全局设计系统。

设计依据为 `outputs/classroom-interaction-design-2026-10-25/index.html`；实施要求与证据边界见 `.impeccable/review/interaction-live-20261025/direction.json`。课堂外壳、真实人数姓名、实际教学内容以及新增评分区会随业务状态变化，不能用空白画布与静态示例课件的差异判定设计一致性。

**当前状态：本地实现及主要业务链已验证，最终构建与 overlay lint 均退出 0；独立窄范围复审 disposition 为 `ship`。** 首轮要求修正的长解析越界、重复重开图标和催交覆盖提交区 3 项均已修正并补拍。最终复审仅覆盖这 3 项及变更区域的可见回归，不代表所有设备、主题和状态的像素一致性认证。

## Typography

互动表面沿用系统字体（`-apple-system`、`BlinkMacSystemFont`、`Segoe UI`、`PingFang SC`、sans-serif），基准正文为 12px / 1.5。聊天题干为 14px / 1.65、600 字重；学生浮题题干为 15px / 1.65，手机竖屏改为 14px。人数、状态、时间等辅助信息通常为 11px；答案正文采用 12px / 1.7，学生文字输入为 13px / 1.7。

题干、答案和解析保留换行，并允许长词换行。数字人数使用等宽数字特性。辅助文字的小字号是局部高密度信息布局，不是全站正文大小。

## Layout

**原卡处理规则。** 老师在聊天题卡内完成已答/待答查看、单人答案查看、修改提示、催交和答案下发，核心操作不要求离开课堂；高级管理入口保留。

| 表面 | 当前代码中的几何 |
| --- | --- |
| 聊天题卡 | 宽度随容器；内容常用横向内边距 14px，分组间距 6–12px |
| 学生浮题 | 桌面宽度 350px，最大宽高为宿主减 24px；内容内部可滚动，提交区 sticky |
| 手机竖屏浮题 | `max-width: 719px` 且 portrait 时宽度为宿主减 24px；选项最小高度 43px |
| 完整名单 | body portal、fixed 定位；宽 310px，最多视口减 24px；最大高度 `min(345px, 100dvh - 24px)`，内部滚动 |
| 出题区 | 桌面受聊天区高度限制并内部滚动；操作栏 sticky；手机竖屏独占聊天内容区，隐藏消息列表和消息输入栏 |

**工具栏避让规则。** 学生浮层宿主根据真实课堂 dock 顶部位置计算底部安全区（额外留 12px；无法测量时回退 88px）。浮题拖动限制在宿主边界内（8px）；宿主及题卡尺寸由 `ResizeObserver` 重新测量，以覆盖窗口变化与解析展开。胶囊也按实际舞台右边缘定位，手机使用右侧 12px。验收必须检查展开解析后的卡片底部与 dock，不只检查初次打开状态。

## Elevation & Depth

聊天题卡以细线分隔为主；脱离聊天流的浮题、名单和提醒才使用轻阴影。当前浮题阴影为 `0 14px 38px #20242b1c`，名单为 `0 12px 32px #20242b1a`；这组局部浮层深度不覆盖全局卡片规范。浮题宿主不拦截舞台指针事件，只有实际浮层和按钮可交互。

## Shapes

题卡、浮题和名单使用 12px 圆角；主要按钮和输入常用 8px；选项为 7px；状态胶囊和提醒为 10px。头像为圆形，重叠组最多展示 4 人与余量，单个头像外加与表面同色的 2px 间隔边。完整名单不依赖头像组的截断数量。

## Components

### 学生浮题与胶囊

未答的活动题自动打开；标题拖柄支持指针拖动和键盘方向键（12px，Shift 为 40px）。关闭或 Escape 隐藏浮题，可从题目图标或聊天题卡重开；浮题已经打开时不再显示独立重开图标。草稿按课堂、用户和题目分键保存在 `sessionStorage`；关闭浮层保留草稿，成功提交后清除草稿并自动切为已答胶囊。活动期间可重新编辑；关闭或老师下发后只读。

跨设备提交通过 `expectedVersion` 和答案版本检测冲突。冲突时保留当前草稿并提供读取最新答案的入口；不能静默覆盖另一端成功提交的内容。重试遇到已经保存的相同答案时可恢复为已答状态。

### 老师头像名单、答案和历史

已答、待答分别显示稳定用户 ID 对应的头像和人数。鼠标移入或键盘聚焦展开名单，点击固定展开，触屏用点按；名单支持外部点击、Escape 和关闭按钮退出。选中已答学生后，答案直接在原卡展开，显示提交次数、提交时间、最新答案和上次答案；完整历史数据由服务端保存，紧凑卡片仅展示上一次。

修改圆点和修改提示以 `answerVersion` 与当前会话已读版本比较；修改答案不会增加作答人数。当前详情通过课堂刷新事件即时请求，并每 3 秒轮询兜底，联网和页面可见性变化也刷新；“实时”不意味着已经证明所有网络下的固定延时。

### 持久催交

老师可催全部待答或指定一名待答学生。服务端筛选未答者、记录收件人，使用请求 ID 保证同次请求可重放，并执行题目级 30 秒冷却。离线学生重连后可以读到提醒；已答学生不会收到待答提醒。

学生提醒使用 `role="status"`，不抢输入焦点，最多显示 10 秒，铃铛摆动两轮；本地记录已展示的提醒 ID。打开题卡时，提醒放在标题下方的正常内容流中，不再用外部 toast 覆盖提交区；题卡关闭或胶囊状态才显示外部 toast。减少动态偏好会关闭动画、过渡和自动平滑滚动。提醒是数据库记录驱动的课堂通知，并非外部消息推送服务。最终 390×844 截图与窄范围复审确认内联提示、4 个选项、提交操作及独立 dock 同时可见。

### 真实 AI 出题、预览与发布

老师输入要求和题型后请求真实生成接口；生成结果进入直接可编辑的预览，可修改题干、选项、正确答案/参考答案和解答逻辑。生成与发布是两步，只有老师明确发布才创建并开始活动；手动出题仍可用。重新生成当前预览不会改写已发布题目的既有答案与结果。发布使用请求 ID，重复提交同一内容可恢复同一创建结果；新题开始会关闭前一道活动题。

### 判分与老师主动下发

客观题由服务端按答案判分；`shortText` 与 `essay` 提交后进入后台 AI 评阅，记录状态、分数、正确性和理由。AI 失败保留学生作答，老师可重试；活动关闭后可直接人工评分。人工评分和异步 AI 更新受响应版本约束，旧 AI 结果不能覆盖更新的答案或已保存的人工评分。当前后台执行不是持久化任务队列；进程中断后的恢复依靠老师重试或人工评分。

**老师下发规则。** 下发前，学生响应由服务端去除正确答案、参考答案、解析、成绩和 AI 评阅理由，同时不返回同学名单/答案。老师显式下发才进入 `published`，结束作答窗口并向学生开放结果与解析；尚有未完成评分时拒绝下发，不应仅在前端隐藏字段。

### 白板自动工具：独立设计稿

`outputs/classroom-interaction-design-2026-10-25/whiteboard.html`、`whiteboard.css`、`whiteboard.js`、`whiteboard-direction.json` 和 `whiteboard-notes.md` 是单独的设计原型，本次没有接入业务白板源码。

原型约定：进入白板自动展开工具，桌面位于画布左侧、手机位于画布内底部；颜色/粗细按需展开，同一时间一个二级浮层；只读角色隐藏编辑工具；清空二次确认。正式接入应复用现有 Fastboard controller，不能把原型 canvas 的演示能力当成真实 SDK 集成。文字工具仅示意插入位置。

## Do's and Don'ts

- **Do** 保持已批准稿的内容顺序与紧凑操作，验证长答案、展开解析、手机出题和完整名单等具体状态。
- **Do** 保留可见焦点、图标可访问名称、触屏替代 hover 的路径，以及减少动态偏好。
- **Don't** 把结果隐私交给 CSS、把关闭浮题当作删除草稿，或把 AI 生成完成当作已经发布。
- **Don't** 将旧截图、局部浏览器检查或孤立服务测试写成全设备、全主题或生产验收通过。

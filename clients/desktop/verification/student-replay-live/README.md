# 真实学生回放计时与课节撤权

2026-11-12，`feature/classin-unified-workspace`。使用已存在的独立 Chrome 学生 rainy/test 会话，以及内置浏览器教师 test1 会话；未提取或注入登录凭据。

## 实际业务链路

- 学生首页读取真实班级，只显示已加入班级，没有学生/分组管理入口。正常进入原课节的互动记录，显示“仅展示你的作答”，展开本人已发布答案 A、正确、10/10；没有教师的学生选择器或全班作答入口。
- 在专用本地 Docker 数据库创建临时班级、已结束课节和完成录像记录，沿用原测试师生身份。唯一媒体是上传到实际 OSS 的合成 H.264 测试图：50 秒、640×360、6,258,485 字节；不是课堂录制或真实人员视频。
- 学生经正常网页和 API 解码媒体，使用页面下拉框切换 1.5×，实际视频时间推进到 32.4042 秒。真实 PostgreSQL 两次读取相隔 16 秒，累计时长由 6 秒增加到 21 秒，保存的课节绑定及倍速均正确；后续终态累计 28 秒。重新开始播放，页面读回 `00:00:28`。
- 教师独立预览同一视频并暂停于约 31.439 秒。数据库仅有 rainy 一条进度，没有教师进度；没有调整服务端时钟或伪造心跳响应。
- 初次实测计时失败，服务日志为旧 Prisma Client 不认识 `playbackLessonId`，而独立新进程可读取该字段。停止旧本地开发进程并启动原命令后修复，原师生登录保持有效；README 补充生成客户端后必须重启开发服务。

## 撤权缺陷与修复

仅在临时课节新增当前学生的显式排除规则。真实列表过滤掉该课节时，录像读取已开始；选中课节被清空，旧读取的清理函数取消请求，旧 `finally` 不再更新状态，页面因此一直显示加载。

- 新增 `playback-stability.cjs --missing-lesson-only`，先稳定复现“无视频但一直加载”的失败。
- 空课节分支现在同步清理录像数据、加载和错误状态；微任务带取消标志，避免旧清理覆盖新的选择。
- 隔离回归确认权限提示替代持续加载，恢复名单后点击页面重试重新读取课节并播放。真实学生重复验证相同操作：撤权后播放器数量为 0，显示无权访问；只移除本轮新增排除规则后，点击“Reload recordings”恢复 50 秒、640×360 视频。
- 本轮没有改变 OSS 签名有效期；页面及新请求的撤权不等于撤回此前已经发出的媒体地址或内容。

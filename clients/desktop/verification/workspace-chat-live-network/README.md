# 工作台班级聊天与私聊：真实账号弱网验收

2026-11-12，在本地 Docker `classin_unified_dev` 使用已有教师 test1 与学生 rainy/test 的真实登录会话。迁入独立 worktree 后继续执行，未替换认证、接口返回内容或客户端消息实现。

## 已观察到的结果

- 班级聊天：教师发送后立即出现待发送消息；学生最终收到同一内容。首个发送回执设置为延后 8 秒，但没有取得足以证明学生在回执之前收到的时序证据，因此不作该延迟承诺。
- 班级聊天：学生发送的首个 HTTP 回执在实际写入后断开，重新打开页面后师生均显示该消息。数据库中班级消息共两条，每条各一行。
- 私聊：教师通过“发起私聊”选择本次临时班级和 rainy，学生用对应会话入口读取。首个发送回执设置为延后 15 秒，教师在回执返回前刷新；刷新前后均可见同一待发送文本，随后师生均显示已保存消息。
- 私聊：学生输入未发送草稿后刷新，同一标签页恢复完整草稿；之后替换为测试回复并发送。
- 私聊：学生回复的首个 HTTP 回执在写入后丢失，记录到第二次 POST 返回 201；最终师生双方均显示该回复。此处不将浏览器传输层重发与应用重试调度混为一谈。
- 私聊共两条数据库消息。教师发送中刷新与学生丢回执场景各出现两次成功 POST，但数据库每条内容各一行，`senderId + clientId` 无重复。
- 迁移后的根目录 1049 项测试、桌面端 107 项测试均通过。迁移前 TypeScript 检查通过；这是本次涉及行为的自动化基线，不等于整个项目的最终验收。

# Unified classroom workspace

Mode: Operate. Approved reference: http://127.0.0.1:3183/ and clients/desktop/design/classin-v5/. This is an implementation of the user's chosen system, not a new concept round. Scope includes the website and Electron; the prior client-only restriction is superseded by the explicit shared-web goal.

## Direction contract

THESIS: A compact teaching workspace lets a teacher find a class, prepare a lesson, manage people and enter live teaching without changing visual systems between web and desktop.

OWN-WORLD: Preserve the approved 13px system type, white paper, light-gray navigation, black primary actions and restrained green status. Existing nature covers remain the visual contrast; provenance stays with the v5 assets.

STORY: The user first recognizes their classes and upcoming work, opens a class or a task, and reaches authenticated teaching and review functions. Real data, permissions, pending writes and recoverable errors remain visible.

FIRST VIEWPORT: A 44px centered search/next-class/plus bar sits over a rounded workspace. A 156px sidebar ends in the account menu. Class cards occupy the center; a 264px task rail sits right. Calendar, directories and course workspaces use the corresponding approved column topology.

FORM: User-pinned ClassIn-referenced v5 operate workspace; no randomized seed or alternative composition is applicable. The signature interaction is selecting a class or scheduled lesson while preserving workspace context and time-zone clarity.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

## In-progress boundary

The goal is active. Home, calendar, tasks, course chat and the personal drive have shared React implementations; Electron uses the same entry. The course landing page now uses the approved three-column structure, while management subpages and replay still use their prior layout. Private chat, some drive operations, course activities, permissions and end-to-end verification remain incomplete. Finish review and design documentation occur after the full goal is implemented.
